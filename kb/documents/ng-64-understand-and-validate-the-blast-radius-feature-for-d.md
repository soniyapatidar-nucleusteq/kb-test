# NG-64: Understand and validate the Blast Radius feature for demo

Source: NG-64

Understand and validate the Blast Radius feature for demo

Type: Story
Status: Done

As a team, we want a clear picture of what the Blast Radius feature does today and how much of it actually works, so that we can demo it confidently and know what is still outstanding.
Blast Radius is meant to answer one question during an incident: if this component fails, what else goes down with it? That tells us how serious a problem is and who needs to be told. Before showing it to anyone, we need to know which parts are finished, which are unused, and how to run a reliable demo.
Scope
Trace the feature from the graph data through to what appears on screen

Identify which versions are in use and which are leftover or incomplete

Confirm what actually works against a running environment

Write down demo steps anyone on the team can follow

Raise any defects found as sub-tasks

Acceptance criteria
The feature is explained in plain language, including how it differs from Root Cause Analysis

Working versions are confirmed against a live environment; unused ones are listed so we don't present them

Repeatable demo steps are documented, including which project to use

Defects found during the review are logged
